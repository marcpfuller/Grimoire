# Grimoire

Grimoire is a local shell-capture daemon for Red Team evidence collection. It
opens an operator's normal Bash or Zsh session inside a PTY, records each
command and its output as structured SQLite data, serves an embedded React UI,
exports selected commands as Asciinema v2 recordings, and can push completed
commands to one or more SpecterOps Ghostwriter oplogs.

The current repository builds one `grim` binary. The daemon, authenticated HTTP
API, SQLite store, shell launcher, Ghostwriter synchronization, service manager,
and production web UI all ship in that binary.

## Current Capabilities

- Opens instrumented Bash and Zsh sessions without modifying the operator's
  permanent shell configuration.
- Assigns every pane a stable ID and a readable generated name; `--name` can set
  a custom name of up to 20 characters.
- Reserves collision-checked seven-character command IDs before execution and
  records command text, prompt, timing, exit status, and raw PTY output chunks.
- Stores panes, commands, output, tags, annotations, pending ID reservations,
  and sync state in a local SQLite database using WAL mode and forward-only
  migrations.
- Provides session history, tagging, annotations, search, output review, and
  multi-command `.cast` export through the CLI or embedded web application.
- Authenticates API requests, except the non-sensitive liveness probe, with a
  local bearer token created with mode `0600` on first daemon start.
- Streams command, session, tag, deletion, and sync changes to the UI over
  server-sent events (SSE).
- Discovers Ghostwriter oplogs from multiple service tokens and routes each pane
  to its selected oplog.
- Supports automatic background sync or explicit one-command sync.
- Installs as a user-level launchd service on macOS or systemd service on Linux.
- Deletes an individual command and all command-owned records, or a pane and all
  of its commands, through authenticated API endpoints.

## Requirements

- Go 1.25 or newer
- Node.js 20 or newer and npm for frontend generation and builds
- macOS or Linux for background-service installation
- Bash or Zsh for automatic shell-hook injection

SQLite is provided by the pure-Go `modernc.org/sqlite` module. No external
database or Docker service is required.

## Build

On a fresh checkout, install frontend dependencies and generate the ignored
artifacts before building:

```bash
npm --prefix web ci
make typegen
make build
```

The binary is written to `dist/grim`. `make build` compiles `web/dist/` first,
then embeds it in the Go binary. Install it in a directory on your `PATH`, for
example:

```bash
install -m 0755 dist/grim "$HOME/.local/bin/grim"
```

Generated artifacts are intentionally ignored:

- `web/src/api/generated.ts` is generated from Go API types by `make typegen`.
- `web/dist/` is generated by the Vite production build.
- `internal/db/mocks/` is generated by `make mocks`.

Cross-compile the Linux AMD64 binary with:

```bash
make build-linux
```

## Configuration

Pass an explicit configuration file with `--config`. Without that flag,
Grimoire looks for `config.yaml` in this order:

1. `~/.grim/`
2. `~/.config/grimoire/`
3. `./config/`
4. The current directory

A configuration file is optional for local-only capture because defaults are
built into the binary. Create one when using Ghostwriter or when runtime config
changes must persist:

```yaml
server:
  host: "127.0.0.1"
  port: 7777

sync:
  interval_seconds: 30

ghostwriter:
  url: ""
  tokens: []
  auto_sync: true

cast:
  dir: ""

log:
  dir: "."
  filename: "grimoire.log"
  level: "info"
  max_mb: 50
  max_backups: 5
```

Important defaults and behavior:

| Key | Default | Behavior |
| --- | --- | --- |
| `server.host` | `127.0.0.1` | HTTP API and web UI listen address |
| `server.port` | `7777` | HTTP API and web UI port |
| `db.path` | `~/.grim/grimoire.db` | SQLite database shared by daemon and shell recorder |
| `auth.token_path` | `~/.grim/token` | Local API bearer-token file |
| `shell` | `$SHELL`, then `/bin/sh` | Shell executable used by `grim shell` |
| `sync.interval_seconds` | `30` | Background sync interval |
| `ghostwriter.url` | empty | Ghostwriter base URL |
| `ghostwriter.tokens` | empty | Service tokens used to discover and route oplogs |
| `ghostwriter.auto_sync` | `true` | Automatically push finalized commands |
| `cast.dir` | next to DB in `casts/` | Default `.cast` output directory |
| `log.filename` | `grimoire.log` | Rotating structured log filename |

The omitted `db.path` and `auth.token_path` keys use their home-directory
defaults shown above. If you override them in YAML, use absolute paths; literal
`~` values are not shell-expanded.

`grim service install` writes the currently resolved settings to the canonical
`~/.grim/config.yaml` used by the installed service.

Do not commit Ghostwriter service tokens or the local daemon token. Binding the
server to a non-loopback address exposes a bearer-authenticated plain HTTP API;
put an appropriate secure transport in front of it.

## Start the Daemon

Run it in the foreground:

```bash
grim daemon start
```

The first start creates the SQLite database and local bearer token. The web UI
is available at `http://127.0.0.1:7777` with the default configuration.

Stop a foreground or otherwise reachable daemon cleanly with:

```bash
grim daemon stop
```

For a user-level background service:

```bash
grim service install
grim service status
grim service restart
grim service stop
grim service uninstall
```

Service installation uses a launchd LaunchAgent on macOS and a systemd user
unit on Linux; it does not require root.

## Capture a Shell

Start the daemon before opening an instrumented shell:

```bash
grim shell
```

When Ghostwriter is configured and stdin is interactive, omitting `--oplog`
opens an oplog selector. If no oplog is available, Grimoire can continue in
local-capture mode.

```bash
# Resolve by Ghostwriter oplog ID or name
grim shell --oplog 42
grim shell --oplog "External Assessment"

# Set the pane name shown in the web UI
grim shell --oplog 42 --name web-prod
```

Grimoire creates a temporary Bash init file or Zsh `ZDOTDIR`, sources the
operator's normal rc file, injects its hooks and completion, then removes the
temporary files when the shell exits. The hooks reserve an ID at prompt time,
record command start/end through the daemon, and delimit the corresponding PTY
output with OSC markers.

If the daemon becomes unreachable, the shell remains usable and reports the
capture interruption; commands executed while it is unavailable are not
recorded.

## CLI Reference

| Command | Purpose |
| --- | --- |
| `grim shell [--oplog ID_OR_NAME] [--name NAME]` | Start an instrumented shell |
| `grim history [--pane ID | --all]` | List recorded commands |
| `grim tag --id SHORT_ID LABEL...` | Attach one or more labels |
| `grim cast SHORT_ID... [--out PATH]` | Export selected commands as Asciinema v2 |
| `grim sync SHORT_ID [--oplog ID]` | Push one command to Ghostwriter now |
| `grim config get [group.key]` | Read daemon configuration |
| `grim config set group.key value` | Update a scalar runtime setting |
| `grim config set --append ghostwriter.tokens TOKEN` | Add a service token |
| `grim config set --del ghostwriter.tokens` | Select and remove a service token |
| `grim daemon start|stop` | Run or stop the daemon directly |
| `grim service install|status|restart|stop|uninstall` | Manage the background service |

### History

`grim history` uses `$GRIMOIRE_PANE_ID` inside an instrumented shell. Use
`--pane` outside that shell or `--all` to list every pane. Output columns are
`ID`, `TIMESTAMP`, `DURATION`, `EXIT`, and `COMMAND`.

### Cast Export

All selected IDs must belong to one pane. IDs may be unordered,
non-contiguous, or repeated; synthesis sorts by pane sequence and removes
duplicates. Inter-event pauses longer than two seconds are compressed.

```bash
grim cast abc0001
grim cast abc0012 abc0001 abc0005
grim cast abc0001 abc0012 --out "$HOME/recordings/recon.cast"
```

## Ghostwriter Synchronization

Set the Ghostwriter base URL and one or more service tokens with `OPLOG_RW`
access:

```yaml
ghostwriter:
  url: "https://ghostwriter.example.com"
  tokens:
    - "gwst_replace_me"
  auto_sync: true
```

At daemon startup, each usable token queries Ghostwriter for its accessible
oplogs. Grimoire builds an oplog-to-token routing map; a failed token is skipped
when at least one other token initializes successfully. Commands inherit the
selected oplog from their pane.

Automatic sync processes finalized, unsynced commands on the configured
interval. Set `ghostwriter.auto_sync` to `false` to retain commands locally
until explicitly pushed:

```bash
grim sync a1b2c3d
grim sync a1b2c3d --oplog 42
```

The `--oplog` override applies only to that push and is not persisted. A
successful push inserts a Ghostwriter OplogEntry containing command text,
cleaned output, timestamps, and the Grimoire short ID.

The config API hot-applies changes to the sync interval, automatic-sync flag,
and log level. `cast.dir` is read on the next export. Ghostwriter URL/token
changes and other logging changes are persisted but require a daemon restart.

## Web UI

The embedded React UI currently provides:

- Session navigation using readable pane names and per-command sync status.
- Command output with terminal color rendering and unsafe control sequences
  removed.
- Editable operator, tool, user-context, source/destination IP, description,
  comments, and tag metadata.
- Tag-grouped navigation and command-text search.
- Multi-select Asciinema export.
- Runtime settings editing for the config API's writable keys.
- Live session, command, tag, deletion, and synchronization refresh over SSE.

Development mode uses the mock API by default:

```bash
npm --prefix web run dev
```

The production build uses the real daemon API and is embedded by `make build`.

## HTTP API

The daemon serves the UI and API on the same listener. Every `/api/` route
except `/api/health` is protected by the daemon bearer token. The embedded HTML
receives the token at request time so the browser client can authenticate
without a separate login.

| Method and path | Purpose |
| --- | --- |
| `GET /api/health` | Liveness probe (`200 OK` with an empty body) |
| `GET /api/sessions` | Panes and ordered command summaries |
| `GET /api/tags` | Tags joined with their commands |
| `GET /api/commands/{id}/output` | Cleaned command output |
| `GET`, `PATCH /api/commands/{id}/metadata` | Read or update annotations and tags |
| `DELETE /api/commands/{id}` | Delete a command, output, tags, and metadata |
| `DELETE /api/panes/{id}` | Delete a pane and all associated records |
| `GET`, `POST /api/config` | Read or update writable settings |
| `GET /api/oplogs` | List oplogs discovered from configured tokens |
| `POST /api/cast` | Export selected command IDs |
| `POST /api/sync` | Push one command immediately |
| `GET /api/events` | SSE event stream |
| `POST /api/shutdown` | Graceful daemon shutdown |

Shell hooks also use `/api/next-id`, `/api/register`, `/api/execute`,
`/api/precmd`, and `/api/deregister`. `grim tag` uses `/api/tag`.

## Storage Model

The main SQLite tables are:

- `panes`: stable pane identity, display name, dimensions, and Ghostwriter
  oplog snapshot.
- `commands`: monotonic internal ID, unique short ID, pane sequence, prompt,
  timing, exit code, and sync status.
- `output_chunks`: raw PTY bytes with offsets from command start.
- `tags`: unique labels per command.
- `command_metadata`: operator annotations used by the UI.
- `pending_commands`: one reserved short ID per active pane.

Command IDs use SQLite `AUTOINCREMENT` so deleting the highest command cannot
cause a stale PTY or sync reference to identify a later command. Deletion is
transactional and explicitly removes child records before the owning command or
pane.

## Current Limitations

- Automatic hook injection is implemented only for Bash and Zsh. Other shells
  start without injected capture hooks.
- `scrub.rules` is present in the example configuration but custom regex secret
  replacement is not wired into capture or sync. Current scrubbing removes
  terminal control sequences only.
- The web UI's Ghostwriter status is currently a placeholder rather than a real
  connectivity check. Its daemon-health client also expects a JSON response
  while `/api/health` currently returns an empty `200 OK`, so the displayed
  daemon state does not yet reflect the liveness endpoint correctly.
- Command/pane deletion and manual one-command sync exist in the API, but are
  not currently exposed as web UI actions.
- Ghostwriter synchronization inserts new OplogEntry records. It does not update
  an existing remote entry or attach generated `.cast` files as evidence.
- The planned `grimshell` and offline recorder binaries are not implemented;
  only `cmd/grim` is built today.
- The SQLite database is local and unencrypted. Protect the host, database,
  configuration file, and token file according to the sensitivity of captured
  terminal data.
